# CONTRACT_GAPS

Places where neither `docs/FRONTEND_SPEC.md` nor the backend master spec defines the behaviour.
Each entry names the single function that holds the assumption. Nothing here adds endpoints,
fields, enum values, tables or libraries.

| ID | What is undefined | Where | Assumption (isolated in one function) |
| --- | --- | --- | --- |
| CG-001 | Body and error code of `GET /ready` when it returns 503. Backend spec 8 fixes only the status code. | `GET /ready` | 503 with the normal error envelope. `code` is `MODEL_UNAVAILABLE` when the model is not loaded, `INTERNAL_ERROR` when only the database is down. Failing checks are reported through the documented `details[{field,issue}]` shape as `{component, state}`. `app/main.py::readiness_error_code` |
| CG-003 | The error table has no entry for HTTP statuses other than 400/401/403/404/409/422/429/500/503 (for example 405, 413, 415, 502). | all routes | Status `< 500` maps to `BAD_REQUEST`; status `>= 500` maps to `INTERNAL_ERROR`, except the statuses listed in the table. `app/core/errors.py::error_code_for_status` |
| CG-004 | `request_id` format, and whether an inbound `X-Request-ID` is honoured. | all responses | A fresh UUIDv4 per request, always generated server-side; an inbound value is ignored. Returned in the envelope and in the `X-Request-ID` response header. `app/core/logging.py::new_request_id` |
| CG-005 | `ALLOWED_ORIGINS` encoding. | CORS | Comma-separated list, entries trimmed, empty entries dropped. `*` is rejected at startup because credentials are allowed. `app/core/config.py::parse_origins` |
| CG-006 | How `/ready` checks the database, and how long it may take. | `app/db.py` | `SELECT 1` on the configured engine with a 3 second connect timeout; any `SQLAlchemyError` means not ready. `app/db.py::check_database` |
| CG-007 | Text and shape of `details[].issue`, and how Pydantic locations become `field`. | every 422 | `field` is the Pydantic `loc` with `body`/`query`/`path`/`header`/`cookie` prefixes removed and dots between nested keys; `issue` is the Pydantic message verbatim (English, may change with Pydantic versions). `app/core/errors.py::validation_details` |
| CG-008 | Startup behaviour for invalid configuration. | process start | **Resolved 2026-11-07, accepted as written.** `RuntimeError` is raised while importing `app.core.config`, so the process exits non-zero and never serves a partially configured app. A missing `DATABASE_URL` in staging or production aborts startup; there is no localhost fallback. `app/core/config.py::load_settings` |
| CG-009 | Backend spec section 6 says `numeric` without precision for several columns. | schema | **Accepted 2026-11-07.** `weight_kg` is `numeric(10,2)`; `predicted_dwell_days` `numeric(10,4)`; `predicted_occupied`/`total_capacity` `numeric(12,3)`; `utilization_pct` `numeric(6,2)`; money stays `numeric(18,2)`, rates `numeric(18,4)`. `migrations/versions/0001_initial.py::upgrade` |
| CG-010 | Nothing defines how seeded rows are identified, so "idempotent seed" has no key to rely on. | `scripts/seed_dev.py` | **Accepted 2026-11-07.** Every seeded row gets `uuid5(namespace, "portiq:dev-seed:<natural key>")`; ports, profiles and shipments are also looked up by their natural key first. A re-run inserts only missing rows and never overwrites edits. `scripts/seed_dev.py::_seed_id` |
| CG-011 | `tariff_rules.rate_value` is `NOT NULL`, but `rate_type="tiered"` carries its rates in `tier_config`, so there is no meaningful single rate. | tariff seed | **Accepted 2026-11-07.** Tiered demo rules store `rate_value = 0.0000`; the cost engine (B08) reads `tier_config` for tiered rules and ignores `rate_value`. `scripts/seed_dev.py::TARIFFS` |
| CG-012 | `profiles.email` uniqueness is not stated, but dev-mode login looks a user up by email, so duplicates would be ambiguous. | `profiles` | **Accepted 2026-11-07.** `email` is `UNIQUE`. `migrations/versions/0001_initial.py::upgrade` |
| CG-013 | Section 7 defines automatic profile creation only for valid Supabase tokens and says the dev token is "for a seeded user", but it does not say what happens for an unknown dev email or an inactive profile. It also does not say what a Supabase token with a non-UUID `sub` or no `email` claim should do. | `get_current_user` | **Accepted 2026-11-07.** Unknown or malformed `dev:<email>` → 401 `UNAUTHENTICATED` (dev mode never auto-creates profiles). A Supabase token with a non-UUID `sub` or no usable `email` claim → 401 `UNAUTHENTICATED`, because `profiles.id`/`email` are required. An inactive profile → 403 `FORBIDDEN` with message "Account is inactive"; the profile row is kept. `app/core/deps.py::get_current_user` |
| CG-014 | Section 8 does not define: how `arrival_from`/`arrival_to` are typed, how unknown body fields are handled on `POST`/`PATCH /shipments`, whether explicit `null` or an empty patch is a change, what a created or transition event's `event_type`/`occurred_at` is, the response shape of `PATCH` and event posts, the audit `action`/`before`/`after` shape, the tie-break for "newest first", the status code of an event post, or a maximum event note length. | `PATCH /shipments/{id}` (+ shared shipment helpers) | **Accepted 2026-11-07.** `arrival_from`/`arrival_to` are dates and bound `expected_arrival_at` inclusively by whole UTC day. Unknown body fields (including `status`, `owner_user_id`, `reference`, `port_id`) → 422; no field is silently accepted. `PATCH` ignores explicit `null` values and an empty body is a 200 no-op that does not touch `updated_at`. `PATCH` returns `Shipment`; `POST /shipments` and `POST /shipments/{id}/events` return `ShipmentDetail` and the event post is 200. The create event's `occurred_at` is the request time; transition `event_type` is the `to_status` value. Audit rows use `action="shipment.<to_status>"`, `before={"status": <old>}`, `after={"status": <new>, "occurred_at": <Z>}`. Newest-first tie-breaks on `id desc` for shipments and predictions. Notes are trimmed, blank notes become `null`, and a note longer than 500 characters → 422 with `details[0].field="note"`. `app/api/v1/shipments.py::update_shipment` |
